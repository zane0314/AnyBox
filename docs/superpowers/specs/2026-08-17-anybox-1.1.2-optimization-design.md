# AnyBox 1.1.2 优化设计

日期：2026-08-17

基线版本：AnyBox 1.1.1（238）

目标版本：AnyBox 1.1.2（239）
包名：`com.zane.proxy`

## 1. 目标

本次优化解决四类问题：

1. 智能策略出口不再依赖香港、日本、美国等固定地区名称，而是使用用户首页中真实存在的节点组、节点、直连或拒绝。
2. 智能策略可管理应用、域名和远程规则引用，并能手动或自动更新引用规则。
3. 普通路由规则可逐条选择位于现有应用策略组之前或之后，并能在软件界面中正常展开、查看和编辑。
4. 从 1.1.1 覆盖安装到 1.1.2 时保留节点、节点组、普通路由、智能策略、规则引用、缓存和分应用代理数据。

本次修改必须改变最终生成的 sing-box 配置和实际流量路径，不能只调整 UI。

### 1.1 术语边界

- `智能策略组`就是当前智能分流页面已有的`应用策略组`，两者是同一个功能，不新增第三套规则组。
- YouTube、Netflix 等内置卡片以及用户新建的卡片，都是该应用策略组中的单个智能策略。
- 每个智能策略可以组合应用、域名和远程规则，并统一选择节点组、具体节点、直连或拒绝出口。
- `普通路由规则`是另一套路由规则，可逐条放在应用策略组之前或之后。
- 原有`分应用代理`只控制哪些 Android 应用进入 VPN，不是第三套路由规则组。

## 2. 已验证的 1.1.1 基线

- 智能策略由 `SmartRoutingStore`、`SmartRoutingSnapshot`、`SmartRoutingTargetHelper` 和 `SmartRoutingRuleConfigHelper` 独立管理，不依赖普通路由设置。
- 节点组选择保存为 `group:<id>`，具体节点保存为 `node:<id>`。
- 选择整个节点组会生成该组对应的 urltest/竞速出口；选择具体节点会绑定该节点。
- 智能策略已经支持 Karing `.srs` 和自定义 `.list/.srs` URL；`.list` 具备最近一次成功缓存。
- 普通路由使用 `RuleEntity.prioritizeOverSmartRouting` 字段，但当前 `takesPriorityOverSmartRouting()` 会把所有非主代理出口强制判为前置。
- 最终路由当前已分成普通规则前段、智能策略和普通规则后段，sing-box 按列表首条命中。
- “路由规则”卡片本身具备展开逻辑；错误入口来自三点菜单跳转到 `AssetsActivity`。
- 全局已存在 `rulesUpdateInterval`，用于 sing-box 远程 RuleSet 的 `update_interval`。

## 3. 方案选择

### 方案 A：复用现有路由、存储和更新链路（采用）

- 智能策略继续使用 `SmartRoutingStore`。
- 普通路由继续使用 `RuleEntity` 和 `RouteSettingsActivity`。
- 前置/后置继续复用 `prioritizeOverSmartRouting`，不修改 Room schema。
- `.srs` 继续交给 sing-box 远程 RuleSet 机制。
- `.list` 继续使用 `SmartRoutingRuleHelper` 下载、解析和缓存。
- 自动更新时间继续使用 `rulesUpdateInterval` 作为唯一间隔来源。

优点是改动最小，覆盖安装风险最低，不会形成第二套路由系统或第二套规则存储。

### 方案 B：把智能策略写入普通路由数据库（不采用）

这会混淆智能策略、普通路由、规则顺序和删除关系，并破坏每个智能策略独立选择节点组的模型。

### 方案 C：应用自行下载并管理全部 `.srs` 二进制缓存（暂不采用）

它能完全控制强制更新时间，但会重复 sing-box 已有的远程 RuleSet 下载、缓存和校验能力。只有当前核心无法提供可验证的手动刷新能力时，才考虑在后续版本采用。

## 4. 智能策略出口

### 4.1 可选项

每个内置或自定义智能策略显示：

- 关闭；
- 自动；
- 直连；
- 拒绝；
- 首页当前存在的全部节点组；
- 展开节点组后显示该组当前存在的全部具体节点。

节点组从数据库实时读取。导入、创建、删除或重命名节点组后，智能策略列表同步反映，不维护固定地区清单。

### 4.2 真实路由语义

- `group:<id>`：绑定该节点组生成的 urltest/竞速出口，自动选择延迟最低的可用节点。
- `node:<id>`：绑定指定节点。
- `direct`：生成到现有 `bypass`/直连出口的规则。
- `reject`：生成到现有 `block`/拒绝出口的规则。
- `off`：不生成该智能策略规则。
- `auto`：保持 1.1.1 的自动选择语义。

当已保存的节点组或节点被删除时，界面显示“目标已失效”，配置生成不得引用不存在的 outbound；该策略临时回退为 `auto`，但保留原 token，便于同 ID 数据恢复时重新生效。

## 5. 智能策略匹配规则

### 5.1 应用选择

继续使用现有“选择应用”功能。应用包名规则属于对应智能策略，不进入普通路由规则。覆盖安装必须保留已选应用。

### 5.2 自定义域名

每个智能策略新增“自定义域名”入口，允许多条规则。添加时用户只填写域名或关键词，并选择：

- `DOMAIN`：只匹配完整域名；
- `DOMAIN-SUFFIX`：匹配根域名及全部子域名，默认选项；
- `DOMAIN-KEYWORD`：域名中包含指定关键词。

例如输入 `youtube.com` 并选择 `DOMAIN-SUFFIX`，最终生成对 `youtube.com` 及其子域名的 `domain_suffix` 匹配。用户不需要手写 `DOMAIN-SUFFIX,youtube.com`。

规则保存时去除首尾空白和完全重复项。空值不得保存。自定义域名与该策略的应用规则、内置规则及远程引用共同指向同一真实出口。

### 5.3 远程规则引用

保留 1.1.1 已有能力：

- 在线搜索 Karing `sing` 分支 `ACL4SSR` 目录中的 `.srs`；
- 添加、替换、删除多个自定义 HTTP(S) `.list/.srs` URL；
- `.list` 支持 `DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`IP-CIDR` 和 `IP-CIDR6`；
- 每条引用都绑定所属智能策略当前选择的节点组、节点、直连或拒绝出口。

规则引用属于智能策略，不复用普通路由设置，也不要求用户编辑整段 sing-box JSON。

## 6. 引用规则更新

### 6.1 界面控件

智能策略规则区域新增三个控件，继续使用现有 Liquid Glass 卡片、MaterialButton、颜色和间距：

1. `立即更新全部引用规则`；
2. `自动更新间隔`；
3. `连接后首次检查延迟`。

更新结果显示：检查总数、成功数、无变化数、等待核心更新数、失败数、最后成功更新时间和失败原因。单条失败不得中止其他规则。

### 6.2 手动更新

点击“立即更新全部引用规则”后：

1. 收集所有智能策略保存的 URL；
2. 按规范化 URL 去重，避免同一来源重复下载；
3. `.list` 立即下载并解析，只有内容有效时才原子替换最近一次成功缓存；
4. `.srs` 优先调用当前运行核心可安全访问的内部 RuleSet 刷新入口；
5. VPN 正在运行且 `.list` 内容实际变化时，所有下载完成后只执行一次配置重载，不按 URL 重启；
6. VPN 未运行时，新缓存从下一次连接开始生效。

当前 1.1.1 Java 桥接层未发现可直接调用的 RuleSet 刷新方法，因此 1.1.2 按以下固定降级语义实施：只有在候选核心中验证到安全的进程内入口并收到成功结果时，`.srs` 才计入“更新成功”；否则该条显示“等待核心按更新周期刷新”，计入“等待核心更新数”，继续由 sing-box 的 `update_interval` 更新。不得伪造成功，不得为此默认开放无鉴权的 Clash API，也不在本版本新增一套应用侧 `.srs` 二进制缓存系统。

### 6.3 自动更新间隔

继续使用现有 `rulesUpdateInterval`，不新增重复的更新周期字段。界面提供预设：

- 关闭；
- 6 小时；
- 12 小时；
- 24 小时，新安装或尚无该配置时的默认值；
- 3 天；
- 7 天。

已有自定义合法值必须保留并显示，覆盖安装时不能被 24 小时默认值覆盖。`0` 继续表示关闭自动更新；关闭后不执行连接后检查和长连接周期检查，手动更新仍可使用。

### 6.4 每次连接后的首次检查

用户已确认采用以下语义：每次 VPN 连接成功后执行一次延迟检查，而不是仅设备启动后的第一次连接。

- 默认延迟：30 秒；
- 可选：立即、15 秒、30 秒、1 分钟、5 分钟；
- 只有距离上次成功更新已经超过自动更新间隔时才下载；
- 没有成功更新时间时视为已过期；
- 成功时间按规范化 URL 分别记录，多个策略引用同一 URL 时共享一次下载结果；
- 检查在后台进行，不阻塞 VPN 建立、DNS 初始化和节点测速。

### 6.5 长连接

VPN 保持连接时，按照自动更新间隔继续检查。调度复用现有服务生命周期和后台执行能力，不增加常驻自建定时线程。Android 休眠或省电策略可能延迟执行，界面不得承诺秒级准时。

更新失败时：

- 保留旧缓存和当前配置；
- 不断开 VPN；
- 下一次按正常周期检查，用户也可手动重试；
- 不形成无间隔重试循环。

## 7. 普通路由规则

### 7.1 路由规则入口

智能分流页中的“路由规则”卡片点击后在当前页面展开或收起规则列表。三点按钮复用同一展开逻辑，不再跳转到 `AssetsActivity`。

- 加号：进入现有新建路由规则流程；
- 每条规则的铅笔：进入现有 `RouteSettingsActivity` 编辑器；
- 列表直接显示规则名称、启用状态、出口和“前置/后置”位置。

不新建第二套路由编辑器。

### 7.2 每条规则的位置

所有普通路由规则，无论自带、升级前已有还是新建，都可以手动选择：

- `前置`：位于应用策略组之前；
- `后置`：位于应用策略组之后。

界面不再使用含糊的“开启/关闭”文案。复用现有 `prioritizeOverSmartRouting` 布尔字段：`true` 表示前置，`false` 表示后置。出口类型不再强制决定位置。

规则详情和列表摘要显示：

```text
前置 · 拒绝
后置 · 直连
前置 · 节点组 A
后置 · 节点 B
```

### 7.3 最终优先级

最终 sing-box 路由顺序固定为：

```text
前置普通路由规则
        ↓
应用策略组（即智能策略组）
        ↓
后置普通路由规则
        ↓
默认出口
```

同一段普通路由继续按 `userOrder` 排序；智能策略继续按 `routingPriority` 排序。sing-box 首条匹配即停止，因此：

- 去广告、恶意域名拒绝等需要覆盖应用策略的规则应设为前置；
- 漏网之鱼、流量兜底、最终直连等应设为后置；
- 现有应用策略组本身的位置和内部逻辑不改变。

### 7.4 升级迁移

当前 1.1.1 会把所有非主代理出口规则自动放到智能策略前面。为了覆盖安装后不改变既有行为，1.1.2 首次运行执行一次幂等迁移：

- 已有 `outbound != 0` 的规则写为前置；
- 已有 `outbound == 0` 的规则保留原 `prioritizeOverSmartRouting`；
- 新建规则默认后置；
- 去广告/拒绝预设明确创建为前置；
- 兜底直连预设明确创建为后置。

迁移只更新现有字段，不修改或重建路由表。所有规则更新成功提交后才写入完成标记；中途退出时可安全重复执行。用户之后可逐条调整。

## 8. 数据保存与覆盖安装

1. 保持包名和签名连续，使用覆盖安装，不卸载、不执行 `pm clear`。
2. 不删除或重建 `sager_net.db`、`configuration.db`。
3. 不修改现有 Room schema；新增简单状态优先保存在现有 PreferenceDataStore。
4. 必须保留：
   - 节点和节点组；
   - 节点组成员关系；
   - 普通路由规则及顺序；
   - 每条路由规则的前置/后置值；
   - 智能策略及其节点组/节点/直连/拒绝选择；
   - 选择的应用；
   - 自定义域名；
   - 规则 URL、最近成功缓存、更新时间和状态；
   - 原有分应用代理数据。
5. 删除自定义智能策略时，只清理该策略自己的域名、URL 和缓存，不影响其他策略。

## 9. UI 一致性

- 新按钮、列表、输入框和弹窗复用现有 Liquid Glass 样式。
- 使用主题属性和现有 drawable，不硬编码新的背景色、圆角或阴影。
- 节点组展开层级与 1.1.1 保持一致。
- 网络任务显示进行中状态，主线程不得下载规则。
- 所有状态必须如实显示，不能把“已提交检查”显示成“更新成功”。

## 10. 验证标准

### 10.1 静态与构建

- `versionName=1.1.2`、`versionCode=239`；
- 包名仍为 `com.zane.proxy`，应用名仍为 AnyBox；
- apktool 强制全量构建成功；
- zipalign 通过；
- apksigner v1/v2/v3 验证通过；
- 无临时调试 JSON、测试 URL 或诊断代码残留。

### 10.2 最终配置

必须检查实际生成的 sing-box JSON，而不只检查 UI：

- 节点组目标生成 urltest/竞速出口；
- 具体节点目标直接绑定该节点；
- 直连映射到 `bypass`；
- 拒绝映射到 `block`；
- 自定义域名类型映射正确；
- `.list/.srs` 引用绑定到所属策略的真实出口；
- 路由顺序严格为前置普通路由、智能策略、后置普通路由、默认出口。

### 10.3 更新机制

- 手动更新会检查所有去重后的 URL；
- `.list` 只有下载和解析成功才替换旧缓存；
- 单条失败不影响其他 URL；
- 连接 30 秒后仅在过期时自动检查；
- 长连接达到周期后再次检查；
- 更新失败不停止 VPN，旧缓存继续生效；
- `.srs` 只有收到核心成功结果时才显示更新成功；无安全刷新入口时显示“等待核心按更新周期刷新”。

### 10.4 覆盖安装与运行

- 安装前后导出并比较数据库；能逐字节比较的数据库必须 `cmp` 一致，发生预期迁移时逐表核对差异；
- 节点、节点组、路由、智能策略、应用选择和规则数据均保留；
- VPN 实际启动并保持运行；
- 日志无 `FATAL EXCEPTION`、`VerifyError`、`ClassCastException`、`NoSuchMethodError` 或 `IllegalAccessError`；
- 使用测试域名和测试应用验证流量实际经过目标节点组、节点、直连或拒绝。
