# AnyBox 1.2.1 规则系统收敛与真实 ASN/文本规则支持设计

## 1. 结论

项目存在两套实际参与配置生成的规则入口，不是单一规则系统：

1. 智能策略规则链：SmartRoutingRuleHelper → SmartRoutingStore → SmartRoutingRuleConfigHelper → ConfigBuilderKt。
2. 普通路由规则链：RuleEntity → ConfigBuilderKt.appendUserRules → SingBoxOptionsUtilKt.makeSingBoxRule/processRulesetUrl。

两套入口分别拥有不同的输入格式、缓存、错误处理和 sing-box 生成逻辑。这是 ASN/国外 .list 报错和“已有转换器却没有复用”的主要结构性原因。

本设计只针对 1.2.1，当前不修改代码、不构建 APK。目标是先收敛规则语义和错误边界，再实施最小代码改动。

## 2. 扫描范围与已验证事实

扫描范围包括：

- apktool_out/smali/io/nekohasekai/sagernet/routing/SmartRoutingRuleHelper.smali
- SmartRoutingStore.smali、SmartRoutingRuleConfigHelper.smali、SmartRoutingRuleUpdateHelper.smali、SmartRoutingTargetHelper.smali
- SmartRoutingFragment.smali、RouteSettingsActivity.smali、RuleEntity.smali 及其 DAO
- apktool_out/smali/moe/matsuri/nb4a/SingBoxOptionsUtilKt.smali
- ConfigBuilderKt.smali、AnyBoxConfigPatcher.smali
- support/SmartRoutingRuleUpdateHelper.java、support/SmartRoutingTargetHelper.java
- sing-box 规则模型、资源和 geoip/geosite 资产

已验证事实：

- 智能策略解析器支持 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6。
- 智能策略有 URL 下载、文本缓存、最近一次成功缓存和真实 route rule 生成。
- 普通路由从 domains、ip、ruleset 三个字段分别生成 sing-box 规则。
- 普通路由的 ruleset 当前只接受 rsip: 和 rssite:，其他内容被跳过。
- 普通路由的 ip 入口会把非 geoip: 的值作为 ip_cidr 候选；URL 不是 CIDR，会使 sing-box 拒绝配置。
- 普通路由当前会跳过 http://、https://、IP-ASN,、ASN,；这只能阻止错误配置，不能提供 ASN 或远程文本规则功能。
- Rule_DefaultOptions 有 ip_cidr、rule_set 等字段，但没有 ip_asn 字段。
- APK 内置 geoip.db.xz 和 geosite.db.xz；扫描未发现应用层 ASN 查询接口，也未发现内核可直接使用 ip_asn 的证据。
- AnyBoxConfigPatcher 是最终配置补丁链，不是第三套规则来源；它负责在最终 JSON 上补 DNS/规则集兼容配置。
- generateRuleSet、rsip:、rssite: 属于普通路由的 sing-box remote rule-set 兼容路径，不是文本 .list 转换器。
- 未发现当前运行路径中另有 mihomo/clash rule-provider 生成器。enable_clash_api 仅是已有配置能力，不能视为本项目当前规则主链。

## 3. 重大问题排序

### P0：普通路由输入 URL 被当作 CIDR

用户把 https://yfamilys.com/rule/ASN-CN.list 或 Global.list 填入普通路由 IP 字段时，当前入口没有调用已有下载/解析缓存链，而是把内容送入 ip_cidr。sing-box 会因 netip.ParsePrefix 失败而拒绝整份配置。

修复要求：URL、文本规则、CIDR、规则集必须在进入 sing-box 模型前完成类型识别和验证；类型不匹配必须返回明确错误，不得过滤后继续生成配置。

### P0：ASN 被误认为 IP-CIDR，且当前没有真实 ASN 能力

ASN-CN.list 的实际内容为 IP-ASN,<ASN>。它不是 CIDR，不能写入 ip_cidr。当前核心模型没有 ip_asn 字段，不能通过改字符串或取消过滤伪造支持。

修复要求：

- 已转换的 IP-CIDR 列表走现有文本规则转换链。
- IP-ASN 只有在实现并验证 ASN 前缀解析数据源后才允许启用。
- 没有 ASN 数据源时，必须以“当前版本不支持 ASN 匹配”的可见错误停止，不得静默跳过。

### P1：两套规则解析器和生成器语义不一致

同样的 .list URL，在智能策略中可以下载、解析、缓存并生成规则，在普通路由中不能复用；普通路由还额外支持 full:、domain:、regexp:、keyword: 等另一种输入语法。

结果是用户无法预测规则应填在哪里，修复一处入口也会遗漏另一处入口。

### P1：错误传播不完整

过去的过滤/跳过逻辑避免了 VPN 直接启动失败，但掩盖了文件格式错误。用户明确要求错误正常报错，因此“忽略不支持行后继续”不再作为修复策略。

### P1：规则来源、缓存和出口绑定耦合

智能策略规则来源天然绑定策略出口；普通路由规则还需要保留自身的前置/后置、包名、端口和出口语义。简单把普通路由改成调用智能策略生成器会破坏普通路由的匹配条件。

## 4. 1.2.1 目标架构

不新增第三套系统，收敛为一个“规则来源解析层 + 两种消费者”架构：

输入来源
  ├─ 内联 sing-box 规则：geoip:/geosite:/full:/domain:/regexp:/keyword:
  ├─ 文本规则 URL：.list 或内容特征识别
  ├─ sing-box 规则集 URL：.srs 或 rsip:/rssite:
  └─ ASN 文本：IP-ASN,<number>
        ↓
统一 RuleSourceResolver
  ├─ ParsedRuleSet：domain/domain_suffix/domain_keyword/ip_cidr/ip_cidr6
  ├─ RemoteRuleSet：srs，URL、tag、缓存路径
  └─ AsnRuleSet：ASN → 已验证 CIDR，含数据源版本
        ↓
  ├─ 智能策略消费者：绑定策略出口
  └─ 普通路由消费者：保留原有匹配条件和出口
        ↓
统一 sing-box 配置校验

解析层只负责识别、下载、解析、缓存和错误；消费者只负责把已验证规则附加到对应 outbound，不再各自解析同一份文本。

## 5. 文本 .list 方案

### 5.1 支持格式

首期复用现有 SmartRoutingRuleHelper.parseList() 的五类语义：DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6。

保留注释、空行和去重行为，但改变错误策略：

- 不支持的非空规则行记录行号、原文类型和原因。
- 文件没有任何有效规则时直接失败。
- 文件同时含有有效行和不支持行时，默认仍失败；只有未来明确增加“允许部分规则”的产品选项后才可部分接受。
- CIDR 必须通过统一地址解析验证。

### 5.2 来源识别

- http:// 或 https:// 先下载，再根据扩展名和内容特征识别 .list 或 .srs。
- .srs 不进入文本解析器，直接走 remote rule-set。
- URL 下载失败时保留最近一次成功缓存，但本次更新操作必须向 UI 报告失败原因。
- VPN 启动时若没有可用缓存，必须阻止生成不完整配置并显示错误。

### 5.3 复用边界

普通路由调用统一来源解析层后，将解析结果附加到它自己的 Rule_DefaultOptions，不得把规则改存到 SmartRoutingStore，也不得丢失普通路由的包名、端口、协议、前后位置和出口。

智能策略继续从 SmartRoutingStore 读取来源和缓存，只替换内部解析调用，不改变已有用户数据格式。

## 6. ASN 真实实现方案

### 6.1 不能直接支持的部分

IP-ASN,<ASN> 不能转换成 sing-box ip_cidr，而当前内置核心和 Java 模型没有直接 ASN 匹配字段。1.2.1 不得把 ASN 行写入 ip_cidr，也不得把它标记为已支持。

### 6.2 推荐实现

增加 ASN 解析适配器，但不增加第二个规则配置系统：

1. 下载带版本号的 ASN 前缀数据源。
2. 解析 ASN → IPv4/IPv6 CIDR 映射。
3. 按 ASN 生成已验证的 ip_cidr/ip_cidr6 规则。
4. 缓存原始数据、数据版本、目标 ASN、解析结果和成功时间。
5. 生成配置前检查结果非空、CIDR 全部合法、数据未超过大小上限。
6. 数据源失败且无旧缓存时阻止 VPN 启动并报错；有旧缓存时允许使用旧缓存，同时显示更新失败。

这条路径的前提是选定一个可审计、可稳定访问、明确授权使用的 ASN 前缀数据源。若无法提供该数据源，1.2.1 只能支持用户已有的 CIDR 转换文件，不能宣称支持 IP-ASN 动态匹配。

### 6.3 用户现有转换文件

用户已有的 .list 转 sing-box 转换能力应作为输入来源的一部分接入统一解析层。已经转换为 IP-CIDR 的文件直接复用现有文本解析器；仍为 IP-ASN 的文件必须经过 ASN 适配器，不得直接交给 sing-box。

## 7. .srs 与内置 geo 规则

- .srs 继续走 sing-box remote rule-set，不经文本解析器。
- rsip:/rssite: 只作为兼容输入前缀，内部统一成 RemoteRuleSet。
- geoip:/geosite: 继续作为已存在的 rule-set 引用，不下载、不转换成文本规则。
- geoip.db/geosite.db 只证明 geo 数据存在，不证明其可用于 ASN 查询。
- AnyBoxConfigPatcher 继续负责最终 JSON 的 DNS/规则集兼容补丁；它不能承担来源下载或文本解析职责。

## 8. 错误和缓存规则

错误必须沿以下链路传播：

来源下载/解析错误 → RuleSourceResolver 结构化错误 → 配置构建失败 → SagerConnection/VpnService 停止 → MainActivity 显示原始原因和来源/行号。

错误分类至少包括：下载失败、HTTP 非 2xx、内容为空、格式无法识别、行格式错误、CIDR 非法、ASN 无数据源、ASN 结果为空、SRS 下载/校验失败和配置模型不支持。

缓存原则：

- 成功缓存不可因失败更新被清空。
- 失败更新必须有可见错误记录。
- VPN 启动只使用可验证的最近成功缓存。
- 缓存内容和来源 URL 必须绑定，避免 URL A 误用 URL B 的旧规则。

## 9. 实施顺序

1. 抽取或复用现有 ParsedRules，先统一 .list 解析和严格错误结果。
2. 将普通路由 URL 识别接入统一来源解析层，保留普通路由条件和出口。
3. 将智能策略更新和配置生成改为消费统一解析结果，保持现有持久化兼容。
4. 统一 .srs/rsip:/rssite: 的来源识别和缓存错误。
5. 单独实现 ASN 数据源适配器；在数据源和实测验证完成前，保持 IP-ASN 明确报错。
6. 清理当前为防崩溃而存在的静默过滤，但保留边界校验和旧缓存回退。

## 10. 验证矩阵

| 场景 | 预期 |
|---|---|
| 普通路由填 Global.list | 下载、解析、生成真实 domain 规则，按普通路由出口生效 |
| 智能策略填 Global.list | 与现有能力一致，规则绑定智能策略出口 |
| 普通路由填 ASN-CN.list | 有 ASN 适配器则生成已验证 CIDR；没有则明确报“不支持 ASN 数据源” |
| 普通路由填 URL 到 IP 字段 | 不再写入 ip_cidr；显示字段类型错误 |
| 文件含一条非法 CIDR | 配置构建失败并显示来源及错误行，不启动半成品 VPN |
| 文件含不支持规则类型 | 显示类型和行号，不静默丢弃 |
| 空文件/全注释文件 | 明确报空规则 |
| 下载失败且有旧缓存 | 使用旧缓存，显示更新失败 |
| 下载失败且无缓存 | 阻止启动并显示失败 |
| .srs/rsip:/rssite: | 走 remote rule-set，不进入文本解析器 |
| 覆盖安装后 | 规则来源、缓存索引、普通路由和智能策略数据保持兼容 |

## 11. 非目标

- 1.2.1 不新增 mihomo/clash 第二套运行核心。
- 不把 IP-ASN 伪装成 ip_cidr。
- 不静默过滤用户文件错误。
- 不删除或重建现有数据库。
- 不把普通路由迁移成智能策略存储。
- 不在没有可验证 ASN 数据源和实机匹配测试前宣称“ASN 已实现”。

## 12. 设计结论

应优化，而且优先级很高：先消除普通路由与智能策略的规则入口分裂，再实现 ASN。当前最小可靠路径是“统一来源解析，保留两种出口消费者”；不是继续给两个解析器分别打补丁。

本设计文档只描述 1.2.1 修复方向，未修改任何代码、数据库或 APK。
