# AnyBox 1.2.1 规则来源快照与解析链收敛设计

## 1. 文档定位

本文件是 AnyBox 1.2.1 的推荐修复设计，基于 2026 年 8 月 19 日完成的全量文件扫描和规则调用链核对。

本轮只写设计，不修改代码、不构建 APK、不安装、不迁移用户数据。

目标：

- 修复普通路由把 HTTP(S) 地址送入 ip_cidr 导致 sing-box 配置失败；
- 不再把 IP-ASN 文本误当作 CIDR；
- 让普通路由复用现有文本规则下载、解析和缓存能力；
- 统一两套规则入口的来源识别、缓存和错误语义；
- 文件错误正常报错，不通过静默过滤伪装成功。

## 2. 已验证事实、推断和未知

### 2.1 已验证事实

项目中存在两套实际参与 sing-box 配置生成的入口：

1. 智能策略链：SmartRoutingRuleHelper → SmartRoutingStore → SmartRoutingRuleConfigHelper → ConfigBuilderKt。
2. 普通路由链：RuleEntity → ConfigBuilderKt.appendUserRules → SingBoxOptionsUtilKt.makeSingBoxRule/processRulesetUrl。

当前普通路由会把 ip 字段中的普通字符串作为 ip_cidr 候选。HTTP(S) URL 和 IP-ASN,ASN 不是 CIDR，因此会触发核心的地址前缀解析错误。

现有 SmartRoutingRuleHelper.parseList() 已能处理 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR 和 IP-CIDR6 等文本规则；普通路由没有复用这条解析和缓存链。

当前扫描到的 sing-box Java 模型没有可直接使用的 ip_asn 字段，也没有能够证明传入 IP-ASN 后由核心原生匹配的实现路径。

AnyBoxConfigPatcher 是最终 JSON 兼容补丁链，不是第三套规则来源系统；它不应负责下载、解析或缓存用户规则文件。

### 2.2 基于事实的推断

当前报错的首要根因不是节点、出口或 VPN 权限，而是规则来源在进入 sing-box 模型前没有完成类型识别和验证。

继续在普通路由入口增加过滤条件只能降低崩溃概率，不能让 ASN 匹配或文本规则真正生效，也会让用户无法知道哪一行文件有问题。

### 2.3 尚未确认的信息

原始 IP-ASN 文件所需的 ASN 到 IP 前缀数据源、授权、版本、更新频率和实机匹配结果尚未确认。因此 1.2.1 不把原始 IP-ASN 宣称为已支持能力。

## 3. 设计结论

采用一个共享的规则来源解析和快照层，保留两个独立的配置消费者：

    规则字段或 URL
      → 来源识别
      → 下载、严格解析、校验
      → 已验证规则快照
      → 智能策略消费者 / 普通路由消费者
      → sing-box 配置校验

共享的只有来源处理：识别、下载、文本解析、SRS 校验、缓存、错误模型和快照读取。

不共享出口生成：

- 智能策略仍绑定当前应用策略组的策略出口；
- 普通路由仍保留包名、端口、协议、前置或后置位置和自身出口；
- 不把普通路由迁移到 SmartRoutingStore；
- 不新增 mihomo、Clash rule-provider 或第三套规则配置系统。

## 4. 1.2.1 的类型化输入约定

### 4.1 普通路由字段

| 字段 | 允许内容 | 禁止内容 |
|---|---|---|
| ip | 真实 IPv4/IPv6 CIDR、兼容的 geoip:* 引用 | HTTP(S) URL、IP-ASN、域名文本、未知规则语法 |
| domains | 域名、域名后缀、关键词等内联域名规则 | 远程 URL、CIDR、IP-ASN |
| ruleset | 远程规则来源 | 把远程 URL 填入 ip 或 domains |

ruleset 字段优先使用显式来源前缀：

- list:https://example.com/rules.list：文本规则文件；
- srs:https://example.com/rules.srs：sing-box 二进制规则集；
- rsip:https://example.com/rules.srs：兼容现有 IP 规则集语义；
- rssite:https://example.com/rules.srs：兼容现有站点规则集语义。

ruleset 字段保留无前缀 HTTP(S) URL 的兼容识别，但保存时归一化为明确前缀。这样旧数据仍可读取，新数据不会依赖字段猜测。

### 4.2 智能策略字段

智能策略继续使用当前 SmartRoutingStore 的规则来源保存方式，不改变已有数据库字段和用户选择结构。内部读取时统一转换为同一个来源描述，再交给共享解析和快照层。

智能策略的规则来源仍绑定策略选择的出口；普通路由的规则来源仍绑定 RuleEntity 自己的出口。

### 4.3 旧数据迁移

发现普通路由 ip 字段中存在 HTTP(S) URL 时：

1. 不静默删除；
2. 不自动覆盖原字段；
3. 不把 URL 继续当作 ip_cidr；
4. 在编辑页显示“该地址属于远程规则来源，请迁移到 ruleset”的明确提示；
5. 用户确认迁移后，才把 URL 复制为 list: 或 srs: 来源；
6. 新来源成功下载并生成快照后，才清理旧 ip 字段。

迁移失败时保留原记录和失败原因，避免一次升级破坏用户现有配置。

## 5. 规则来源快照

### 5.1 快照的职责

快照是下载和配置构建之间的边界。更新阶段负责产生快照，配置构建阶段只消费最近一次成功快照。

正确链路为：

    手动更新或连接后的自动更新
      → 下载来源
      → 检查 HTTP 状态和内容
      → 严格解析或校验
      → 生成已验证快照
      → 临时文件写入完成
      → 原子替换正式快照
      → 更新成功元数据

配置构建期间禁止联网、下载和临时解析远程文件。VPN 启动结果不再依赖网络请求时序，也不会出现同一来源在不同调用路径被解析成不同结果。

### 5.2 快照内容

快照至少包含：

- 规范化后的来源前缀和 URL；
- 来源类型：文本规则、SRS、内置 geo 引用或 ASN；
- 解析成功时间；
- 内容哈希；
- 规则计数；
- 解析器版本；
- 可供配置消费者使用的规则集合；
- 最近一次错误摘要，但错误不能覆盖最近一次成功快照。

快照缓存继续复用当前规则缓存目录和文件生命周期，不新增数据库表。普通路由和智能策略通过来源规范化后的稳定 key 共享来源缓存，但各自用户配置仍保存在原有存储中。

### 5.3 原子写入和失败回退

新快照必须先写入临时文件并完成读取校验，再以原子方式替换正式快照。下载失败、解析失败、内容为空或校验失败时：

- 不清空最近一次成功快照；
- 不把半成品写入正式缓存；
- 手动更新界面显示本次失败原因；
- 自动更新记录失败状态，但不阻止继续使用仍然有效的旧快照；
- 如果没有可用旧快照，配置构建必须失败并显示错误。

旧快照只是明确的可回退运行数据，本次更新失败仍然必须对用户可见。

## 6. 严格文本规则解析

### 6.1 复用范围

1.2.1 复用 SmartRoutingRuleHelper.parseList() 已有的规则语义和去重行为，提取为共享入口或由普通路由直接调用同一实现；不再保留两份格式判断代码。

首期支持：

- DOMAIN
- DOMAIN-SUFFIX
- DOMAIN-KEYWORD
- IP-CIDR
- IP-CIDR6

注释和空行可以跳过，因为它们不是规则；非空规则行不能因未知类型而静默丢弃。

### 6.2 严格错误策略

以下情况均直接产生结构化错误：

- 规则类型未知；
- 规则参数缺失；
- CIDR 不是合法 IPv4 或 IPv6 前缀；
- 文件只有注释和空行；
- 文件包含有效规则与不支持规则的混合内容；
- 内容不是可识别的 .list 或 .srs 格式。

默认采用全文件原子接受策略：只要存在一个非空非法规则行，整份新快照失败。这样不会生成看起来成功但缺少部分规则的配置。

错误至少携带：来源 URL、来源类型、行号、原始规则类型和人类可读原因。例如：

    规则来源 Global.list，第 8 行：IP-ASN 不是 CIDR；1.2.1 未配置 ASN 前缀数据源

### 6.3 用户已有转换链

用户现有的 .list 转 sing-box 规则转换能力作为统一来源解析层的输入适配器复用：

- 已转换为 IP-CIDR/IP-CIDR6 的文件直接进入严格文本解析；
- 已转换为 DOMAIN 系列规则的文件直接进入严格文本解析；
- 仍是 IP-ASN,ASN 的原始文件不能绕过 ASN 适配器直接进入 ip_cidr。

不再另写一套普通路由专用转换器。

## 7. ASN 边界

### 7.1 1.2.1 的明确行为

1.2.1 支持用户已有转换器输出的 CIDR 规则文件。对仍含有 IP-ASN,ASN 的原始文件：

- 不写入 ip_cidr；
- 不转换成伪造的 CIDR；
- 不过滤后继续启动；
- 返回 ASN_UNSUPPORTED；
- 在界面显示“当前版本需要 ASN 前缀数据源，原始 IP-ASN 尚未启用”。

这表示文件错误或能力边界被正常报告，而不是静默降级。

### 7.2 后续原生 ASN 方案

只有在选定可审计、可稳定访问且授权明确的 ASN 前缀数据源后，才进入后续版本评估：

1. 下载带版本号的 ASN 到 IPv4/IPv6 前缀映射；
2. 解析目标 ASN；
3. 生成并校验 ip_cidr/ip_cidr6 快照；
4. 缓存源数据版本、ASN、结果哈希和成功时间；
5. 设置数据大小、过期和失败回退限制；
6. 在真实设备上验证域名解析、IP 匹配和不同出口的实际结果。

在这些条件满足前，不能对外宣称已实现 ASN 匹配。

## 8. .srs、geoip 和 geosite 边界

- .srs 走 sing-box remote rule-set 校验和缓存，不进入文本 .list 解析器；
- rsip: 和 rssite: 作为兼容前缀保留，内部统一到 RemoteRuleSet；
- geoip:* 和 geosite:* 继续作为内置或核心规则集引用，不下载、不转换为文本规则；
- 内置 geoip.db.xz 和 geosite.db.xz 的存在不代表应用具备 ASN 查询能力；
- AnyBoxConfigPatcher 只做最终 JSON 兼容补丁，不承担来源下载、解析、缓存和 ASN 计算。

## 9. 结构化错误与错误传播

共享解析层返回成功快照或结构化错误，不返回过滤后的半成品规则。错误分类至少包括：

| 错误码 | 含义 | 是否可用旧快照 |
|---|---|---|
| SOURCE_INVALID_FIELD | URL 出现在错误字段 | 否，要求修改配置 |
| DOWNLOAD_FAILED | 网络下载失败 | 是 |
| HTTP_STATUS | HTTP 非 2xx | 是 |
| CONTENT_EMPTY | 文件为空或只有注释 | 是 |
| FORMAT_UNKNOWN | 无法识别来源格式 | 是 |
| INVALID_RULE_LINE | 规则类型或参数错误 | 是 |
| INVALID_CIDR | CIDR 非法 | 是 |
| ASN_UNSUPPORTED | 当前版本没有 ASN 前缀数据源 | 是 |
| ASN_EMPTY | ASN 解析结果为空 | 是 |
| SRS_INVALID | SRS 校验失败 | 是 |
| SNAPSHOT_MISSING | 没有成功快照可回退 | 否，阻止启动 |

错误传播链固定为：

    来源下载或解析
      → 结构化错误
      → 配置构建失败或旧快照回退
      → VpnService/SagerConnection 返回原因
      → MainActivity 显示来源、行号和错误

构建失败时不得继续生成一份包含无效 ip_cidr 的配置，也不得用忽略该行的文案伪装成成功。

## 10. 文件和调用链实施边界

只改现有调用链，不新建平行系统：

| 文件或模块 | 1.2.1 职责 |
|---|---|
| SmartRoutingRuleHelper.smali | 保留现有下载和 .list 语义，提供严格解析结果与来源错误 |
| SmartRoutingStore.smali | 保留智能策略来源持久化，读取统一来源描述和快照索引 |
| SmartRoutingRuleUpdateHelper.smali | 只负责触发更新，更新结果交给快照层，不在配置构建时联网 |
| SmartRoutingRuleConfigHelper.smali | 消费已验证快照并绑定智能策略出口 |
| RuleEntity / RouteSettingsActivity | 保留普通路由字段和出口语义，增加字段类型校验与旧 URL 迁移提示 |
| ConfigBuilderKt.smali | 统一调用来源解析或快照读取，再分别附加普通规则和智能策略规则 |
| SingBoxOptionsUtilKt.smali | 只接受已验证 CIDR、内联规则和明确 rule-set 引用，禁止 URL 进入 ip_cidr |
| AnyBoxConfigPatcher.smali | 保持最终配置补丁职责，不加入来源下载或文本解析 |

优先删除或替换当前普通路由中的 URL/ASN 过滤后继续逻辑。边界校验必须保留，静默跳过必须移除。

## 11. 实施顺序

1. 定义来源类型、规范化前缀和结构化错误字段，不改变用户数据库格式。
2. 从现有 SmartRoutingRuleHelper 复用或最小抽取严格 .list 解析入口。
3. 统一下载、校验、缓存和原子快照写入；配置构建只读快照。
4. 将普通路由 ruleset 接入共享来源处理，同时保留普通路由的所有匹配条件和出口。
5. 将智能策略改为消费同一快照结果，保持当前 SmartRoutingStore 数据兼容。
6. 接入 .srs、rsip:、rssite: 的明确来源识别和错误传播。
7. 加入旧数据中 ip 字段 URL 的可见迁移提示和用户确认迁移流程。
8. 对 IP-ASN 保持 ASN_UNSUPPORTED；只有 ASN 数据源经过单独验证后才新增真实转换实现。
9. 删除静默过滤路径，完成配置构建、启动失败和旧快照回退回归。

## 12. 验证矩阵

| 场景 | 预期结果 |
|---|---|
| 普通路由 ruleset=list:Global.list | 下载、严格解析、生成真实规则，并按普通路由出口生效 |
| 智能策略引用 Global.list | 复用同一快照，规则绑定智能策略出口 |
| 已转换的 IP-CIDR 文件 | 成功生成 ip_cidr/ip_cidr6 |
| 原始 ASN-CN.list 含 IP-ASN | 明确显示 ASN_UNSUPPORTED，不生成错误配置 |
| URL 填在普通路由 ip 字段 | 显示字段类型错误，不进入 ip_cidr |
| 文件含一条非法 CIDR | 显示来源和行号，新快照失败 |
| 文件含未知规则类型 | 显示规则类型和行号，不静默丢弃 |
| 空文件或全注释文件 | 显示 CONTENT_EMPTY |
| 下载失败且有旧快照 | 使用旧快照，同时显示本次更新失败 |
| 下载失败且无旧快照 | 阻止 VPN 启动并显示失败原因 |
| .srs/rsip:/rssite: | 走 remote rule-set，不进入 .list 解析器 |
| 普通路由带包名、端口、协议和前后位置 | 这些条件和出口保持不变 |
| 覆盖安装 | 普通路由、智能策略、来源索引和成功快照保持兼容 |
| 配置构建期间断网 | 不临时联网；只读取成功快照 |

静态验证要求：

- 全量搜索 URL 进入 ip_cidr 的调用路径；
- 全量搜索 IP-ASN 被过滤后继续的路径；
- 确认普通路由和智能策略都通过共享来源处理；
- 确认 AnyBoxConfigPatcher 没有承担来源解析职责。

实机验证要求：

- 使用一个有效 .list、一个含非法行的 .list、一个 .srs 和一个原始 IP-ASN 文件；
- 分别测试智能策略和普通路由；
- 验证成功快照、更新失败回退、无快照阻止启动和错误弹窗；
- 验证连接建立后实际路由命中，而不是只验证配置 JSON 能生成。

## 13. 非目标

- 1.2.1 不新增 mihomo 或 Clash 规则运行核心；
- 不把普通路由改存到 SmartRoutingStore；
- 不把 IP-ASN 伪装成 ip_cidr；
- 不静默删除、过滤或忽略用户文件错误；
- 不自动清空或重建用户数据库；
- 不在没有可验证数据源和实机测试前宣称支持 ASN 真匹配；
- 不在配置构建阶段增加网络请求；
- 不为一个实现增加额外工厂、接口层或独立缓存框架。

## 14. 最终决策

1.2.1 的最小可靠实现是“共享规则来源快照，保留两个出口消费者”。

它能真正解决普通路由 .list 不加载的问题，并让错误文件正常报错；同时不会破坏普通路由现有的应用、端口、协议、前置或后置和出口语义。

ASN 的真实匹配不能通过放宽过滤或修改字段名称实现。1.2.1 只接入已有转换器输出的 CIDR 文件，对原始 IP-ASN 返回明确的 ASN_UNSUPPORTED；待数据源、版本和实机命中验证完成后，再单独进入后续版本。

本设计未修改任何代码、数据库或 APK，等待用户审阅后再进入实施阶段。
