# AnyBox 1.2.0 优化设计

日期：2026-08-18

基线版本：AnyBox 1.1.5（242）

目标版本：AnyBox 1.2.0（243）
包名：com.zane.proxy

## 1. 目标

本次优化解决五类问题，全部来自 2026-08-18 实机审计确认的结论：

1. 普通路由规则的"节点组"出口从伪实现改为真实组出口。当前 ConfigBuilderKt.appendUserRules 把 outbound <= -100 的组引用直接解析为主代理 proxy tag，用户选择的组被静默忽略。
2. IP 类路由规则（geoip:cn、自定义 IP-CIDR、.list 的 IP-CIDR 部分）对域名流量生效。当前 sing-box 不会为匹配 IP 规则而解析域名，浏览器/App 的域名连接直接跳过所有 IP 规则。
3. 竞速组（urltest）的测速间隔和容差从硬编码常量改为设置页可选。当前 interval=10m、tolerance=5 写死在 ConfigBuilderKt。
4. 分应用代理/绕过设置与应用分流选择器联动。当前选择器列出全部应用，选中不进隧道的应用会生成静默死规则。
5. 覆盖安装后旧版本残留状态自动清理。当前覆盖安装可能保留旧 :bg 进程或过期服务状态，1.1.3 真机复现过"覆盖安装故障仍在、卸载重装才恢复"。

## 2. 已验证的 1.1.5 基线

以下均经实机（emulator-5554）或代码逐级核实：

- 普通规则组引用编码：outbound = -(groupId) - 100，即 groupId = -(outbound + 100)。RuleEntity 显示名逻辑已按此解码。
- 智能分流的组出口已在 ConfigBuilderKt 生成真实 urltest 出站（tag 经 SmartRoutingTargetHelper.tagFor，URL 取 connectionTestURL，tolerance/interval 常量）。
- 最终路由顺序：前置普通规则 → 智能策略层（包名/域名/引用规则）→ 后置普通规则，sing-box 首条命中。
- IP 规则对域名流量失效已实机 A/B 证实：geoip:cn 开启后 Chrome 访问 baidu.com 仍走主代理；访问 IP 字面量 110.242.68.4 则命中直连（证书错误页=到达真实服务器）。
- 设置页已存在"解析目标地址"（resolveDestination）开关，接入 tun 入站 domain_strategy（genDomainStrategy），默认关闭，自述与 FakeDNS 冲突。
- 内嵌 sing-box 核心 ≥1.12（含 1.12/1.13 弃用提示字符串），支持 route.default_domain_resolver。
- DNS 出站已分 dns-direct / dns-remote / dns-local 等标签。
- 分应用开关与模式：proxyApps 主开关位于设置"路由"分类；逐应用选择与绕过/代理模式由 AppManagerActivity 管理；应用分流选择器复用 AppListActivity（extras：app_list.return_result、app_list.initial_packages）。
- 设置页"路由"分类（cag_route）已有 rulesUpdateInterval 的 SimpleMenuPreference + entries/entryValues 数组模板可复用。
- 失败报错链路（1.1.4）：stopRunner(false,msg) → changeState(Stopped,msg) → MainActivity.stateChanged 弹窗，已实机验证。
- 1.1.5 竞速参数（10m/5ms）为两处常量修改，实装连接正常。

## 3. 详细设计

### 3.1 普通规则节点组真出口

ConfigBuilderKt.buildConfig 生成路由前，先扫描启用规则收集所有 outbound <= -100 的组引用：

- 对每个被引用的 groupId，生成一个 urltest 出站，tag 为 route-group-<groupId>，成员为该组全部启用节点，测速 URL 取 connectionTestURL，间隔/容差读取 3.3 的新偏好。
- 组不存在或无可用节点时回退 proxy tag（保持现状语义）。
- appendUserRules 的 cond_group_outbound 分支改为解析到 route-group-<groupId>，删除 ponytail 简化注释。
- 与智能分流的组出口语义一致：选组=竞速。与智能层各自生成独立出站（tag 不同），不共享，避免互相影响。

不引入 selector 模式；需要手动选节点时用"具体节点"出口（已是真实现）。

### 3.2 IP 规则对域名流量生效

采用 sing-box 1.12+ 的 route.default_domain_resolver：

- 在 RouteOptions 上通过 _hack_config_map 写入 default_domain_resolver，值为直连 DNS 服务器标签（dns-direct）。
- 效果：路由匹配遇到域名连接且存在 IP 类规则候选时，先用直连 DNS 解析再匹配 ip_cidr/geoip/IP rule-set。出口仍收到原始域名，不改变出站拨号语义。
- 与现有 DNS 规则的分工不变：实际拨号解析仍走 DNS 路由表。

权衡（写入用户可见说明）：

- 每个未被域名规则命中的新域名会多一次本地 DNS 查询（毫秒级，有缓存）。
- 若本地 DNS 对被污染域名给出错误答案，可能误判为"中国 IP"而走直连。缓解：域名规则（geosite:cn 等）始终先于 IP 规则命中；该风险只影响"域名规则没覆盖且 DNS 被污染"的少数域名。
- resolveDestination 开关保持现状、默认关闭，作为备选机制（它改变入站语义且与 FakeDNS 冲突，不作为默认方案）。

验证注意：本机 Mac 代理的 fake-ip 会污染模拟器 DNS（实测 baidu.com 返回 198.18.x.x），该项以真机验证为准。

### 3.3 竞速参数偏好化

新增两个偏好（DataStore 字符串类型）：

| 偏好 key | 选项 | 默认 | 作用点 |
|---|---|---|---|
| urlTestInterval | 1m / 5m / 10m / 30m | 10m | 智能分流组出口与 3.1 的 route-group-* urltest 的 interval |
| urlTestTolerance | 5 / 10 / 30 / 50（毫秒） | 5 | 同上两处的 tolerance |

实现：

- res/xml/global_preferences.xml 的 cag_route 分类新增两个 SimpleMenuPreference（复用 rulesUpdateInterval 的写法）。
- res/values/arrays.xml 新增 entries/entryValues 数组（entryValues 直接存 sing-box 可用值）。
- strings.xml 中英文新增标题（如"竞速测速间隔" / "竞速切换容差"），public.xml 分配新 id（取现有最大 string id 递增）。
- DataStore 新增两个字符串偏好代理；ConfigBuilderKt 读取替代常量；tolerance 用 Integer.parseInt。
- 已有用户无迁移：缺省即 1.1.5 的 10m/5ms。

### 3.4 分应用设置与分流选择器联动

在 AppListActivity 的返回选择模式（app_list.return_result=true）下：

- 读取 proxyApps 主开关、逐应用选择集和绕过/代理模式，计算每个应用是否进入隧道。
- 不进隧道的应用：置灰、不可勾选，副标题标注"不会进入 VPN（分应用设置）"。
- proxyApps 关闭时全部应用正常可选（全部进隧道）。
- 只改展示与可选性，不改已保存的选择；已选但后来被排除的应用的规则自然失效，不做自动清理（避免静默删用户配置）。

### 3.5 覆盖安装残留清理

双保险：

1. AndroidManifest.xml 注册 MY_PACKAGE_REPLACED 接收器（exported=false）：收到广播即停止 VPN 服务、将持久化服务状态复位为 Idle，并 killBackgroundProcesses 清理可能残留的 :bg 进程。
2. SagerNet（Application）onCreate 增加版本戳检查：持久化 lastRunVersionCode 与当前不一致时执行同样的复位。覆盖接收器未触发或广播时序异常的场景。

不改变正常升级的数据保留语义：节点、组、规则、策略、缓存全部保留，只复位运行态。

## 4. 影响面与风险

- 3.1 改变真实流量路径：此前选了组出口的规则实际走主代理，升级后将真正走所选组，行为变化需写入更新说明。
- 3.2 为路由层新增解析动作，是最需要真机回归的一项：重点验证中国域名直连生效、代理域名不受影响、首次连接启动时间不显著增加。
- 3.3 仅常量外移，默认值保持 1.1.5 行为。
- 3.4 纯 UI 层。
- 3.5 只在版本变化时触发，正常启动路径多一次整型比较。
- 全部改动不涉及 Room schema，覆盖安装数据全部保留。

## 5. 验证标准

1. 普通规则选「测试竞速组」出口，实机确认流量进入该组 urltest（不再是主代理）；组删除/空组回退主代理不崩。
2. 开启 geoip:cn 前置直连规则，真机 Chrome 访问国内站点直连、代理站点走节点；resolveDestination 保持关闭。
3. 设置页修改间隔/容差后，重连 VPN 生效（可临时插桩导出最终 JSON 核对后撤除）。
4. 绕过模式下被绕过的应用在选择器中置灰不可选；关闭分应用开关后恢复可选。
5. 覆盖安装新版本后，旧 :bg 不残留、界面状态与实际 VPN 状态一致。
6. 回归：1.1.4 失败弹窗、智能策略组出口、规则前置/后置、订阅更新、分应用代理开关。

## 6. 非目标

- 不新增 selector 型组出口；不给普通规则加应用外的新匹配类型。
- 不处理 .srs 手动刷新（无安全刷新入口，维持现状）。
- 不默认启用内置规则（是否出厂启用另行决策）。
- 不修改 Sub-Store 侧任何配置（「CF」订阅的同类隐患已另行告知）。
