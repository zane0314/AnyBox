# 智能策略远程规则引用设计

日期：2026-08-17
目标版本：1.1.1

## 目标

为每个智能策略组增加“规则引用”入口，允许用户填写一个或多个远程规则地址，例如 YouTube.list。规则属于智能策略本身，不进入普通“路由设置”，最终与该策略当前选择的节点组或具体节点绑定。

## 当前事实

- 智能策略内置应用包名和域名来自 SmartRoutingCatalog。
- SmartRoutingStore 已经独立保存智能策略的自定义组、应用包名、地区出口和节点组选择。
- ConfigBuilderKt 将智能策略转换为 sing-box 原生路由规则。
- 用户提供的 YouTube 地址是 Clash/Surge 风格文本列表，不是 sing-box source rule-set JSON。

## 方案比较

### 方案 A：APK 内解析文本规则并生成 sing-box 原生规则（推荐）

APK 使用现有网络库下载规则文本，解析支持的规则行，加入智能策略对应的 sing-box 路由规则，并将出口设置为该策略的节点组或节点。

优点：用户可以直接粘贴现有 .list 地址；不需要额外服务器；规则仍由智能策略统一管理；适合当前反编译代码结构。

代价：需要增加一个小型文本解析器和缓存；不同规则格式需要明确支持范围。

### 方案 B：要求用户提供 sing-box JSON/SRS 地址

直接使用 sing-box rule_set 远程引用。

优点：APK 代码最少。

问题：用户提供的 .list 地址不能直接使用；用户需要额外转换规则；无法满足直接更换规则引用网址的目标。

### 方案 C：把远程规则导入普通路由设置

将下载后的规则写入现有 RuleEntity 路由设置。

问题：智能策略和普通路由的优先级、删除、导入覆盖和出口绑定会混在一起；会破坏当前智能策略独立选择节点组的模型。因此不采用。

## 推荐设计

### 数据保存

规则地址和缓存都使用现有 RoomPreferenceDataStore，键按智能策略组的稳定 ID 区分：

- 规则地址：smartRouting.ruleUrl.<groupId>，值为 URL 列表。
- 最近成功内容：smartRouting.ruleCache.<groupId>.<urlHash>。
- 最近更新时间和解析状态：同一组的附属偏好值。

自定义组改名不影响规则；删除自定义组时同步删除该组规则地址和缓存。覆盖安装时保留这些偏好数据。

### 界面

在每个内置或自定义智能策略组的编辑区域增加“规则引用”按钮。打开后显示：

- 当前 URL 列表；
- 添加 URL；
- 修改 URL；
- 删除 URL；
- 更新规则；
- 最近更新时间、成功/失败状态和支持规则数量。

YouTube 可以预置用户提供的地址，但仍允许修改或删除。

### 支持的文本规则

忽略空行、注释和无法识别的行，转换以下类型：

- DOMAIN,example.com → domain；
- DOMAIN-SUFFIX,example.com → domain_suffix；
- DOMAIN-KEYWORD,example → domain_keyword；
- IP-CIDR,1.2.3.0/24 → ip_cidr；
- IP-CIDR6,2001:db8::/32 → ip_cidr。

USER-AGENT 不转换。Android 应用流量继续使用已有 package_name 匹配；不能把 User-Agent 可靠地推导成应用包名。

### 生成链路

智能策略组
  ├─ 内置应用/域名规则
  ├─ 用户选择的节点组或具体节点
  └─ 规则引用 URL
        ↓ 下载并解析
    最近一次成功缓存
        ↓
    合并为 sing-box 原生路由规则
        ↓
    outbound = 当前节点组/节点

每个 URL 的规则都绑定到同一个智能策略出口。选择整个节点组时，继续使用该节点组已有的竞速/选择逻辑；选择具体节点时，直接绑定该节点。

### 更新和失败处理

- 用户点击保存或更新时下载并解析规则。
- 只有解析出至少一条受支持规则时，才替换该 URL 的旧缓存。
- 下载失败、HTTP 错误、内容为空或全部规则不支持时，保留旧缓存并显示错误。
- 生成配置时只读取缓存，不阻塞代理启动等待网络。
- 没有成功缓存时，继续使用智能策略原有内置规则，不导致整个分流配置失效。

### 验证

至少验证以下内容：

1. 能解析用户提供的 YouTube .list。
2. DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6 能出现在生成的 sing-box 路由规则中。
3. 生成规则的 outbound 是节点组或具体节点，而不是地区名称。
4. URL 修改、删除、重命名策略组后数据关系正确。
5. 下载失败时旧缓存仍生效。
6. 覆盖安装后规则地址、缓存、节点组选择和原有分应用代理数据仍保留。
7. 版本号更新为 1.1.1，APK 能正常构建、安装并启动代理。

## 不做的事情

- 不复用普通路由设置。
- 不让用户直接编辑整段 sing-box 自定义 JSON。
- 不新增规则转换服务器。
- 不把 USER-AGENT 伪装成应用包名规则。
- 不删除现有内置智能策略；远程规则只作为补充或替换该策略的域名/IP规则来源。
