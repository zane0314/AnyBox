# AnyBox 1.3.1 Routing Fixes Implementation Plan

> Execute inline against the existing apktool workspace. Preserve unrelated working-tree changes.

**Goal:** Implement the approved 1.3.1 routing-capture and routing-diagnostics fixes on the 1.3.0 behavior baseline.

**Architecture:** Keep the existing sing-box routing snapshot and VPN lifecycle. Add only the effective package-set merge at the existing VPN builder boundary, and replace the old dynamic probe view with an existing-style menu item and one lifecycle-bound diagnostic helper.

**Tech Stack:** apktool 3.x, Android smali, existing Material/AppCompat resources, Java helper source compiled to DEX/Smali, zipalign, apksigner, aapt2, adb/emulator when available.

## Global Constraints

- 1.3.0 is the only behavior baseline; target versionCode is 250 and versionName is 1.3.1.
- Preserve user proxyApps, bypass, and individual values; merge only at VPN builder configuration.
- Reuse SmartRoutingSnapshot.packagesFor() and existing routing-group state; do not create a second snapshot or matcher.
- Probe only real SOCKS/TLS and /connections evidence; never infer route/IP from DNS or static rules.
- No new service, database, dependency, background pool, or subprocess architecture.
- Do not overwrite or discard existing unrelated working-tree changes.

### Task 1: Baseline and change map

- Decode or inspect 1.3.0 separately and record hashes, versions, and exact baseline methods/resources.
- Map all callers and the existing VPN builder boundary before editing.
- Identify existing menu, dialog, lifecycle, DataStore, and reload patterns to reuse.
- Stop if packagesFor() cannot provide a stable runtime set without duplicating state.

### Task 2: Effective VPN capture set

- Modify only the single existing VPN builder/capture-set boundary.
- Compute S only from active smart-routing groups and valid resolved exits.
- Apply U union S for allow mode and U minus S for bypass mode; leave disabled/global/off behavior unchanged.
- Preserve DataStore and UI lists exactly.
- Add one minimal self-check for off/allow/bypass/duplicates/disabled groups/global mode.

### Task 3: Menu and diagnostic dialog

- Add a non-action menu item beside global mode.
- Remove the old root addView probe entry.
- Reuse MaterialAlertDialogBuilder and existing theme, with input, category selector, result, start/close buttons, progress state, and accessibility labels.
- Normalize and validate hostnames; reject URL, port, and IP input without networking.
- Check VPN, Mixed Inbound, API setting, and 127.0.0.1:9090 before connecting; offer enable-and-reconnect only after confirmation.
- Use unresolved domain:443 through SOCKS, minimal TLS/SNI, one shared 8-second deadline, and RFC3339-compatible matching.
- Close all sockets, streams, and HTTP connections on every exit path.

### Task 4: Version and build

- Set versionName 1.3.1 and versionCode 250 without changing package/min/target SDK.
- Run diff checks, forced apktool build, zipalign, authorized signing if available, apksigner, and aapt2 metadata checks.

### Task 5: Runtime verification and handoff

- Use an isolated API 35 emulator for data setup.
- Upgrade-install 1.3.1 with the same signer; do not substitute uninstall/reinstall.
- Execute routing, diagnostic, regression, and log checks.
- Record APK path, SHA-256, signer, version, commands, and actual evidence in .ai/HANDOFF.md.
- Mark complete only when every design completion gate has evidence.
