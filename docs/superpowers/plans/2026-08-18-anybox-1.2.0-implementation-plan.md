# AnyBox 1.2.0 Implementation Plan

**Goal:** 在 1.1.6 基础上实现设计文档中尚未落地的节点组真出口、选择器联动、覆盖安装清理和竞速参数设置。

**Architecture:** 复用现有 ConfigBuilderKt、Group/Node DAO、AppListActivity 选择器、PreferenceDataStore 和服务状态链，仅在真实配置生成、现有设置页、应用列表过滤及替换广播路径上做最小修改。

**Tech Stack:** Android apktool 反编译工程、smali、现有资源 XML、sing-box JSON。

## Global Constraints

- 版本目标 AnyBox 1.2.0 (243)，包名保持 com.zane.proxy。
- 不修改 Room schema，不新增依赖，不创建平行路由或持久化系统。
- 组不存在或无可用节点时回退 proxy；选择器只置灰不进隧道的应用；覆盖安装清理不删除用户数据库。
- 竞速默认保持 10m/5，只有用户设置覆盖默认值。

### Task 1: 节点组真出口与竞速参数读取

- 在 ConfigBuilderKt 收集启用普通规则的 `groupId = -(outbound + 100)`。
- 为有效组生成独立 `route-group-<id>` urltest，复用 connectionTestURL 和竞速偏好。
- 普通规则组出口改为该 tag；组无效时回退 `proxy`。

### Task 2: 竞速参数设置项

- 在现有 `cag_route` 分类复用 SimpleMenuPreference。
- 提供测速间隔和切换容差候选，默认分别为 `10m`、`5`。
- 验证设置页可见、保存后配置 JSON 反映新值。

### Task 3: 分应用选择器联动

- 读取 proxyApps 开关与 bypass/代理模式。
- 绕过模式下将不进隧道应用置灰并阻止选择；关闭分应用开关时全部恢复可选。
- 保留已有 initial_packages 和 return_result 行为。

### Task 4: 覆盖安装残留清理

- 接收 `MY_PACKAGE_REPLACED`，结合版本戳执行一次性清理。
- 清理旧 `:bg` 进程/过期服务状态，不触碰节点、节点组、路由规则和智能策略数据库。

### Task 5: 全量构建与交付验证

- 强制 apktool 全量汇编、zipalign、签名和 apksigner 校验。
- 安装到 emulator-5554，执行四项回归及崩溃日志扫描。
- 更新 `.ai/HANDOFF.md`，仅在证据齐全后标记完成。
