# AnyBox 1.2.1 Rule Source Snapshot Implementation Plan

> **For agentic workers:** Execute this plan inline against the existing apktool smali workspace. Preserve all unrelated 1.2.0 changes.

**Goal:** Make `.list` text rules and existing converter-produced CIDR rules load through one strict cached source path, while keeping smart-routing and ordinary-routing outbound generation separate.

**Architecture:** Reuse `SmartRoutingRuleHelper` and `SmartRoutingStore` as the only source download/cache/parser path. Add the minimum typed result/error boundary in the existing helper, then make ordinary route construction consume successful cached snapshots and surface failures. Keep `.srs` as a binary sing-box rule-set source and explicitly reject unsupported raw `IP-ASN` input.

**Tech Stack:** apktool 3.0.3, Android smali, existing Kotlin/JVM runtime and sing-box option model.

## Global Constraints

- Do not reset, discard, or overwrite existing 1.2.0 work.
- Do not add a second cache, database table, parser, or network client.
- Never silently drop malformed rule lines or unsupported ASN input.
- Never place an HTTP(S) URL or `IP-ASN,<ASN>` into `ip_cidr`.
- `.srs` is not parsed as `.list`; only existing converter-produced CIDR files are supported in 1.2.1.
- A failed refresh with a valid old cache keeps the old cache and reports the refresh failure; no cache means configuration build fails visibly.
